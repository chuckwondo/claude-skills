## Breaking case + downstream trace, verbatim

### 1. The sibling that already answered the question (plan pass headline)

```
msgspec.json.encode(datetime.timedelta(seconds=21600)) = b'"PT21600S"'
msgspec.json.encode(datetime.timedelta(days=1))        = b'"P1D"'
msgspec.json.encode(datetime.timedelta(days=-3))       = b'"-P3D"'
```

msgspec encodes `timedelta` as ISO 8601 natively. `_axis_from_coord` leaned on that by storing raw `datetime.timedelta` in `Axis.values`. Wire output on `main`, one dataset shape, three dtypes:

```
[h ] "lead":{"values":["P0D","PT3600S"]}      seconds-normalized
[D ] "lead":{"values":["P0D","P1D"]}
[ns] "lead":{"start":0.0,"stop":1.0,"num":2}  unit dropped entirely
```

**Downstream trace:** my plan would have added `PT6H` on the *range* path while the axis path said `PT21600S`. Consumer = any external CoverageJSON reader receiving one document containing both a duration coordinate and a duration data variable (the exact CF shape #189's motivation names). Also `ADR-0021` would have been false at the moment it was written.

### 2. The shortcut that looked like the lazy right answer, killed by running it

```
timedelta64[Y  ] -> int       1
timedelta64[M  ] -> int       1
timedelta64[W  ] -> timedelta datetime.timedelta(days=7)
timedelta64[D  ] -> timedelta datetime.timedelta(days=1)
timedelta64[ns ] -> int       1
timedelta64[ps ] -> int       1
```

`.tolist()` returns `int`, not `timedelta`, for `Y M ns ps fs as`. So "just let msgspec encode it" emits the bare number `1` for one nanosecond and the string `"P1D"` for a day — two JSON *types* for one concept.

### 3. The LBYL probe (second crash, same root cause, not in the issue)

```python
gaps = mask | np.array(
    [hasattr(v, "__float__") and not math.isfinite(v) for v in flat],
    dtype=bool,
)
```

Old vs proposed EAFP probe, over all 11 object-array cases the suite already pins:

```
value                             old probe    new probe
"nan" string                          False        False
np.float32 nan                         True         True
np.longdouble nan                      True         True
np.timedelta64             RAISES TypeError        False  <-- DIFFERS
np.datetime64              RAISES TypeError        False  <-- DIFFERS
```

`np.timedelta64` *has* `__float__`; calling it raises. `hasattr` asks whether the attribute exists, not whether the operation works.

**Downstream trace:** `NdArray.from_numpy(np.array([np.timedelta64(1,"D")], dtype=object), ("x",))` dies in the gap probe *before* any converter runs, for every `data_type`. Not mentioned in the issue.

### 4. Diff-pass headline — regression in a file the diff never touched

Same input, both revisions, two axes:

```
                in-memory          after JSON round trip
main            timedelta64[us]    <U7
this branch     <U7                <U7
```

```
  stored in Axis (main)   : ['timedelta', 'timedelta'] (datetime.timedelta(0), datetime.timedelta(seconds=3600))
  stored in Axis (branch) : ['str', 'str'] ('PT0S', 'PT3600S')
```

Sibling that grounds the asymmetry — a **time** axis survives the wire on both revisions:

```
  TIME after JSON     : datetime64[ns]
```

because `xarray.py:781` keys off the declared reference system: `data = _parse_times(column, system.calendar)`. Nothing declares a duration axis.

**Downstream trace:** `to_xarray(from_xarray(ds))["lead"].dtype` changed for anyone pairing the bridges without serializing. `to_xarray` appears nowhere in the diff.

## Verdict vs true shape

- **Plan pass:** plumb said headline = **2**, scope is wrong, this is "decide how the library represents a duration" not "fix `from_numpy` inference". **Correct.** Drove a real scope change (shared `_duration.py`, both bridges, library-wide ADR) and incidentally fixed two live bugs (`ns` coordinates losing their unit; `datetime.timedelta` stored where `AxisValue = float | int | str | tuple[Any, ...]`).
- **Diff pass:** plumb's *first* verdict was **wrong** and the run corrected it. I initially wrote it up as "a regression I introduced." The two-axis table (in-memory × through-JSON) showed the old in-memory behavior existed *only* because of the type lie being removed, and was already unreachable for anyone who serialized. True shape: **collapsed a divergence between an object and its own bytes**, not "broke a round trip". Materially different claim, and the only defensible one.
- Corollary: a one-axis before/after table would have produced a confident wrong verdict.
